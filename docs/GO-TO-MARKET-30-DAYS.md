# 30-day go-to-market

Goal: earn the first paid audits while making The Extractor useful enough to spread on its own.

## North-star metric

**Paid audits booked.** Stars, impressions and installs are supporting evidence, not the outcome.

## Proof format

Every public piece should use a visible before/after teardown. Do not post abstract “AI slop is bad” commentary without evidence.

Core content unit:

1. screenshot or exact excerpt;
2. one slop finding;
3. why it hurts the human task;
4. delete before replace;
5. reduced version;
6. link to run/install The Extractor.

## Week 1 — proof

- Publish Crown & Core proof case with provenance disclaimer.
- Release `v0.1.0`.
- Record a 45–60 second screen capture: original → findings → R1 reduction.
- Post install commands for Claude Code and Codex.
- Create one GitHub issue template for “Submit a site for extraction.”
- Personally audit 5 public AI-built landing pages; ask owners for permission before using identifiable before/after material as marketing.
- Offer 3 launch audits at $299.

### Instagram
- Reel 1: “I deleted 60% before rewriting one line.”
- Carousel 1: 7 frames — source / human job / slop / delete / gap / human / result.
- Reel 2: booking form choice overload teardown.
- Story: poll — “Which line should die first?” followed by result.

### X
- Daily single finding with screenshot/excerpt.
- Two teardown threads in Week 1.
- Reply to AI-build showcases with useful, specific reductions only when constructive; do not spam plugin links.

## Week 2 — participation

- Add `good first issue` patterns/rules contribution path.
- Publish “The Slop Autopsy #1” and #2.
- Run one public challenge: users submit a page; community votes on what to remove first.
- Ship one contributor-submitted rule only if it passes false-positive review.
- Contact 20 agencies/freelancers with a 3-line offer: free public core + paid white-glove audit.

## Week 3 — distribution

- Publish GitHub Action release/tag and Marketplace listing metadata.
- Submit/import plugin marketplace routes supported by Claude Code and Codex/OpenAI environments.
- Create 3 short demos: copy, UI, product onboarding.
- Publish comparison: “Humanizer vs The Extractor” — rewriting vs deletion-first reasoning. Do not attack upstream projects.
- Ask first paying customers for permission to publish anonymized results.

## Week 4 — convert

- Publish first quantified case study if real measurements exist.
- Add agency waitlist only if agencies have asked for shared rules/reports.
- Raise the one-page audit from launch price only after 3 paid deliveries.
- Decide whether the next build is Team CI, hosted reports, or neither based on buyer requests.

## Viral loops

### Shareable audit artifact
Every report should expose a small public card:
- original element;
- verdict;
- reason;
- what is lost if removed;
- reduced result.

### Contribution loop
New slop patterns can be proposed as PRs, but must include:
- positive example;
- false-positive example;
- reason;
- reversible action.

### Challenge loop
“Can you remove one more thing without hurting the user?” gives creators a repeatable challenge format without claiming a universal aesthetic.

## Content rules

Never:
- fabricate AI authorship;
- shame an individual creator;
- claim a score proves quality;
- publish private client work without permission;
- use ragebait instead of a useful teardown.

The product should spread because the before/after reasoning is inspectable.
