# Monetization: open source without giving away the business

## Classification

**SELL:** The Extractor Deep Audit — a paid, human-reviewed anti-slop teardown that can be sold immediately.

**USE:** The open-source CLI, Claude/Codex skill and GitHub Action — distribution and proof engine.

Do not build a large SaaS before people pay for the audit.

## Offer ladder

### 1. Open Source Core — $0
- local CLI;
- Claude Code plugin;
- Codex plugin;
- GitHub Action;
- public rules and method;
- local reports.

Purpose: adoption, trust, developer distribution and contribution.

### 2. Deep Extraction Audit — $299 launch price
A human-reviewed teardown of one public page or product surface.

Deliverable:
- frozen baseline;
- slop map;
- remove/keep/missing list;
- R1 essential structure;
- R2 human rewrite for the critical path;
- R3 wireframe brief;
- 20-minute recorded walkthrough;
- prioritized next action.

This is the first revenue offer because it can be sold without a hosted platform.

### 3. Extraction Sprint — $1,500–$3,500
For a small site, landing flow or product onboarding.

Adds:
- implementation patch or rebuild brief;
- mobile/accessibility review;
- independent design pass;
- copy + UI cleanup;
- before/after verification.

### 4. Team / Agency layer — build only after demand
Potential paid product:
- private repositories;
- organization rulesets;
- custom protect lists / voice DNA;
- CI policy gates;
- audit history;
- shareable client reports;
- team approvals;
- API.

Do not promise these as live until implemented.

## GitHub Marketplace path

The open-source Action can be listed for discovery. Paid GitHub Marketplace billing requires a **GitHub App**, owned by a verified organization, with monthly and annual plans and `marketplace_purchase` handling. The paid app should therefore be a later distribution layer for Team features, not a blocker for v0.1.

## Plugin-store economics

Treat Claude/Codex/OpenAI plugin directories as acquisition channels first. Keep the core plugin useful without payment. Monetize the service around the plugin:
- paid human audit;
- private team policy;
- hosted report history;
- client white-label reports;
- CI enforcement for private repos.

## Revenue test

Before building the hosted Team layer, prove:
- 10 installs;
- 5 real audits;
- 3 public before/after examples;
- 3 paid Deep Extraction Audits;
- at least 1 repeat/agency buyer.

If those do not happen, improve positioning and proof before adding product surface.
