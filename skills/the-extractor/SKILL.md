# THE EXTRACTOR
Version 0.1.0

## Doctrine

**Understand before editing. Protect what is true. Label what is empty. Delete before replacing. Humanize what survives. Add only what earns its place. Stop when another removal would make the human less successful.**

The Extractor is not a style guide and not an AI-authorship detector. It is a forensic reduction workflow.

## 0. Establish the contract
For substantial work record:
- **MODE:** greenfield or brownfield.
- **OUTCOME:** measurable result.
- **TARGET:** customer, user or system.
- **CONSTRAINTS:** what must not change.
- **PROOF:** evidence required.
- **COMMERCIAL VALUE:** revenue, savings, retention or validated learning.

For an existing product, default to brownfield. Inspect before changing.

## 1. Freeze R0
Capture the current state before critique:
- URL / source / commit / file.
- desktop and mobile render when relevant.
- visible copy, navigation, CTAs, forms, motion, service/product structure.
- analytics or performance evidence if available.
- legal, accessibility and brand constraints.

Never rewrite the only copy of the source.

## 2. Define the human job
Answer:
1. Who is here?
2. Why did they come?
3. What must they understand?
4. What must they believe or verify?
5. What should they do next?

If these are unknown, mark them unknown. Do not fill gaps with marketing assumptions.

## 3. Inventory every meaningful element
Use exactly these verdicts:
- `KEEP VERBATIM`
- `KEEP AND REPOSITION`
- `REDUCE`
- `HUMANIZE`
- `REPLACE WITH EVIDENCE`
- `REMOVE`
- `MISSING AND REQUIRED`

For each deletion, state what is lost. If the answer is a required fact, trust signal, identity, accessibility or action, do not delete it.

## 4. Run eight slop passes
### Copy
Flag portable slogans, staging, inflated claims, generic CTAs, fake contrast, repetitive abstractions and needless explanation.

### Structure
Flag template-shaped information architecture, duplicate sections, repeated conclusions and content that exists only to fill a familiar landing-page skeleton.

### Cognitive load
Flag excessive choices, hidden state, giant selectors, inconsistent CTA labels, required memory and content presented before it becomes relevant.

### Trust
Flag unsupported claims, anonymous proof, numbers without sources, badges without meaning, medical/financial claims requiring substantiation and testimonials whose provenance is unknown.

### Visual UI
Flag decorative containers, generic card grids, arbitrary gradients/glass, default type choices, weak hierarchy and visual effects with no brand or information purpose.

### Motion
Ask: **what does this movement explain?** If nothing, remove it.

### Code
Prefer existing implementation, native platform and installed dependencies. Flag speculative abstraction, duplicate code and AI-shaped comments. Do not code-golf away safety or maintainability.

### Commercial clarity
Ask whether one audience, one problem, one offer, one proof path and one next action are visible. Do not turn a service menu into an acquisition offer.

## 5. Delete before replacing
This is mandatory.

Do not immediately rewrite a generic headline. Delete it first. Inspect the information gap. Only add a new headline if the human needs one.

Produce a subtraction version before a redesign version.

## 6. Reduction scale
- **R0 — Source:** immutable original.
- **R1 — Essential:** remove duplication, filler and unrelated detail; preserve necessary claims and decisions.
- **R2 — Human:** rewrite only what survived R1 in natural, specific language while preserving facts and voice.
- **R3 — Composed:** one dominant idea per screen/section, visible hierarchy, progressive disclosure and obvious next action.
- **R4 — Minimum useful:** remove one more thing at a time until another subtraction damages meaning, trust, identity, accessibility or task completion.

R4 is not always the right final state. Legal and technical material may stop earlier.

## 7. Humanization rules
Humanization means restoring specificity, rhythm, concrete nouns, local context, real evidence and the author's actual vocabulary. It does not mean adding chatty filler.

When available, compare against real author/brand samples. Maintain a protect list of phrases, terms and intentional voice features that must survive.

Never claim text is human-written because it sounds natural.

## 8. Provenance policy
Language patterns can be described as AI-like. They cannot establish authorship or identify a model with reliable certainty.

Use `origin unknown` unless provenance is established by the user, source history or metadata.

Never output an “AI probability” as a factual authorship conclusion. Automated detector research shows substantial out-of-domain, adversarial and false-positive limitations.

## 9. Independent review
The builder may not approve itself.

Use separate passes when available:
- **Reduction critic:** Art of Reduction.
- **Copy critic:** Humanizer / Stop Slop / equivalent.
- **Cognitive critic:** i-have-adhd + Steve Krug principles.
- **Visual critic:** Impeccable.
- **Anti-pattern critic:** anti-slop / taste systems.
- **Accessibility critic:** keyboard, focus, contrast, semantics, reduced motion.
- **Commercial critic:** offer, proof, CTA and measurable next step.

Do not vendor upstream rulebooks into this skill. Read them at their current source when installed and respect their licenses.

## 10. Output contract
For an audit, return:
1. **ORIGINAL / BASELINE**
2. **HUMAN JOB**
3. **PROTECTED**
4. **SLOP MAP**
5. **REMOVE LIST**
6. **KEEP LIST**
7. **MISSING REQUIRED**
8. **R1 ESSENTIAL**
9. **R2 HUMAN**
10. **R3 COMPOSITION**
11. **R4 MINIMUM USEFUL**
12. **PROOF / TEST PLAN**

For each finding use:

```text
ELEMENT
<exact element or excerpt>

VERDICT
<one inventory verdict>

WHY
<specific reason tied to the human task>

WHAT IS LOST IF REMOVED
<answer>

ACTION
<one reversible action>
```

## 11. Release gate
A reduced result fails if it:
- removes required facts or meaningful uncertainty;
- invents proof;
- damages accessibility or error recovery;
- obscures the next action;
- flattens real brand voice;
- breaks mobile use;
- turns a complete legal/technical requirement into a slogan;
- claims production success without verification.

Recommended minimum internal score: 8/10 for meaning, clarity, humanity, economy and medium fit. No critical failure can be averaged away.

## 12. Stop rule
**Stop when nothing else can be removed without making the human less successful.**
